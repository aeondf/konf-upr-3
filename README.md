# Ассемблер и интерпретатор УВМ

Практическая работа №3 по дисциплине «Конфигурационное управление»,
вариант 27.

Учебная виртуальная машина (УВМ) — придуманный компьютер с четырьмя
командами. Программа для неё пишется на языке ассемблера (текстовый
файл CSV), ассемблер переводит её в машинный код.

Сделаны этапы 1–4: ассемблер переводит программу в машинный код,
интерпретатор выполняет все четыре команды (загрузка константы, чтение,
запись, деление) и сохраняет дамп памяти в XML.

## Команды УВМ

Каждая команда занимает 7 байт и состоит из полей. Поле `A` (биты 0—4) —
код операции, остальные поля — операнды.

| Команда | Код `A` | Поля | Что делает |
|---|---|---|---|
| загрузка константы | 0 | `B` — биты 5—20, `C` — биты 21—42 | `память[B] = C` |
| чтение из памяти | 26 | `B` — биты 5—20, `C` — биты 21—36 | `память[C] = память[память[B]]` |
| запись в память | 10 | `B` — биты 5—20, `C` — биты 21—36 | `память[память[C]] = память[B]` |
| деление | 4 | `B` — биты 5—20, `C` — биты 21—36, `D` — биты 37—52 | `память[D] = память[память[B]] / память[C]` |

`B`, `C`, `D` — адреса (16 бит, от 0 до 65535), у загрузки константы
`C` — сама константа (22 бита, от 0 до 4194303).

## Язык ассемблера

Программа — файл в формате CSV, одна строка — одна команда:

```
команда,B,C[,D]
```

| Команда | Пример | Значение |
|---|---|---|
| `const` | `const,327,452` | записать число 452 в ячейку 327 |
| `read` | `read,786,303` | в ячейке 786 лежит адрес; взять число по этому адресу и записать в ячейку 303 |
| `write` | `write,124,13` | в ячейке 13 лежит адрес; записать туда число из ячейки 124 |
| `div` | `div,371,880,359` | в ячейке 371 лежит адрес делимого, в ячейке 880 — делитель; частное записать в ячейку 359 |

Правила:

- имя команды можно писать любыми буквами (`const`, `CONST`);
- числа — десятичные (`452`) или шестнадцатеричные (`0x1C4`);
- пробелы вокруг запятых не важны;
- пустые строки и строки, которые начинаются с `#`, — комментарии.

Пример — программа с тестами из спецификации
([programs/spec.csv](programs/spec.csv)):

```
# Загрузка константы (A=0, B=327, C=452)
const,327,452
# Чтение значения из памяти (A=26, B=786, C=303)
read,786,303
# Запись значения в память (A=10, B=124, C=13)
write,124,13
# Деление (A=4, B=371, C=880, D=359)
div,371,880,359
```

## Ассемблер

```
./run.sh asm --input ПРОГРАММА.csv --output РЕЗУЛЬТАТ.bin [--test]
```

| Параметр | Что это |
|---|---|
| `--input` | файл с текстом программы (CSV) |
| `--output` | двоичный файл-результат |
| `--test` | режим тестирования: показать байты каждой команды |

Ассемблер работает в два шага:

1. **Текст → внутреннее представление.** Каждая строка становится
   словарём «поле → значение», например `{"A": 0, "B": 327, "C": 452}`.
2. **Внутреннее представление → машинный код.** Значения полей
   сдвигаются на номер своего первого бита и складываются в одно число,
   которое записывается в 7 байт, младший байт первым.

Пример для `const,327,452`:

```
A = 0     → 0
B = 327   → 327 << 5  = 0x28E0
C = 452   → 452 << 21 = 0x38800000
сумма       = 0x388028E0 → байты E0 28 80 38 00 00 00
```

Ассемблер записывает машинный код в файл `--output` и печатает его
размер. В режиме тестирования он ещё печатает байты каждой команды в том
же виде, что и тесты в спецификации:

```
$ ./run.sh asm --input programs/spec.csv --output out/spec.bin --test
0xE0, 0x28, 0x80, 0x38, 0x00, 0x00, 0x00
0x5A, 0x62, 0xE0, 0x25, 0x00, 0x00, 0x00
0x8A, 0x0F, 0xA0, 0x01, 0x00, 0x00, 0x00
0x64, 0x2E, 0x00, 0x6E, 0xE0, 0x2C, 0x00
Size of out/spec.bin: 28 bytes
```

Байты совпадают с тестами из спецификации. На этапе 1 в режиме
тестирования печатались поля (`A=0, B=327, C=452`) — по заданию это
нужно было только на том этапе.

**Ошибки** (сообщение `error: ...` и код 1): нет файла, неизвестная
команда, не то число операндов, операнд не число, операнд не помещается
в своё поле, нельзя записать результат (нет папки). В сообщении указан номер строки:

```
$ ./run.sh asm --input bad.csv --output bad.bin
error: bad.csv:1: C=4194304 does not fit in bits 21-42 (0..4194303)
```

## Интерпретатор

```
./run.sh vm --input ПРОГРАММА.bin --dump ДАМП.xml --range НАЧАЛО-КОНЕЦ
```

| Параметр | Что это |
|---|---|
| `--input` | двоичный файл с программой (результат ассемблера) |
| `--dump` | XML-файл, куда сохранить дамп памяти |
| `--range` | адреса для дампа, например `1200-1204` (оба конца включены) |

**Память.** Память УВМ — один список из 65536 ячеек (адреса 0—65535,
столько помещается в 16-битное поле адреса). Команды и данные лежат в
одной памяти: программа загружается с адреса 0, по байту в ячейку.
Поэтому данные нужно класть после программы — во всех примерах они
начинаются с адреса 1000.

**Цикл интерпретатора.** Для каждой команды по порядку:

1. прочитать 7 байт из памяти;
2. перевести их обратно в поля (`{"A": 26, "B": 1000, "C": 1002}`);
3. выполнить команду по коду `A`.

Программа заканчивается, когда кончаются команды. После этого
интерпретатор сохраняет ячейки из `--range` в XML:

```
$ ./run.sh vm --input out/copy.bin --dump out/copy.xml --range 1200-1204
Executed 25 commands
Memory 1200-1204 saved to out/copy.xml
```

```xml
<?xml version='1.0' encoding='utf-8'?>
<memory start="1200" end="1204">
  <cell address="1200">10</cell>
  <cell address="1201">20</cell>
  <cell address="1202">30</cell>
  <cell address="1203">40</cell>
  <cell address="1204">50</cell>
</memory>
```

**Ошибки** (сообщение `error: ...` и код 1): нет файла программы,
размер программы не делится на 7, адрес за пределами памяти, программа
затёрла свою команду, деление на ноль, нельзя записать дамп. Неверный `--range` отсекает argparse (код 2).

### Тестовая программа: копирование массива

[programs/copy.csv](programs/copy.csv) копирует 5 чисел из ячеек
1100—1104 в 1200—1204. Переходов в УВМ нет, поэтому каждый элемент
копируется отдельно, четырьмя командами:

```
const,1000,1100
const,1001,1200
read,1000,1002
write,1002,1001
```

1. `const,1000,1100` — в ячейку 1000 кладём адрес, откуда читать;
2. `const,1001,1200` — в ячейку 1001 кладём адрес, куда писать;
3. `read,1000,1002` — ячейка 1002 = память[память[1000]] = память[1100];
4. `write,1002,1001` — память[память[1001]] = ячейка 1002, то есть
   ячейка 1200 получает число из 1100.

В дампе 1200—1204 те же числа, что и в 1100—1104: `10 20 30 40 50`.

### Тестовая программа: деление

Деление — единственная операция АЛУ (арифметико-логического устройства)
в этом варианте. Команда `div,B,C,D` берёт делимое по адресу из ячейки
`B`, делитель — из ячейки `C`, а целую часть частного записывает в
ячейку `D`. Остаток отбрасывается, деление на ноль — ошибка.

[programs/div.csv](programs/div.csv) делит пять пар чисел, частные
записываются в ячейки 1200—1204. Одно деление — четыре команды:

```
const,1100,100
const,1110,7
const,1000,1100
div,1000,1110,1200
```

1. `const,1100,100` — делимое 100 в ячейку 1100;
2. `const,1110,7` — делитель 7 в ячейку 1110;
3. `const,1000,1100` — в ячейку 1000 кладём адрес делимого;
4. `div,1000,1110,1200` — ячейка 1200 = 100 / 7 = 14.

| Ячейка | Деление | Результат |
|---|---|---|
| 1200 | 100 / 7 | 14 |
| 1201 | 81 / 9 | 9 |
| 1202 | 5 / 10 | 0 |
| 1203 | 4194303 / 3 | 1398101 |
| 1204 | 42 / 1 | 42 |

```
$ ./run.sh asm --input programs/div.csv --output out/div.bin
Size of out/div.bin: 140 bytes
$ ./run.sh vm --input out/div.bin --dump out/div.xml --range 1200-1204
Executed 20 commands
Memory 1200-1204 saved to out/div.xml
```

```xml
<memory start="1200" end="1204">
  <cell address="1200">14</cell>
  <cell address="1201">9</cell>
  <cell address="1202">0</cell>
  <cell address="1203">1398101</cell>
  <cell address="1204">42</cell>
</memory>
```

## Как запустить

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```sh
uv sync                      # поставить зависимости
./run.sh asm --help          # справка по параметрам ассемблера
./run.sh vm --help           # справка по параметрам интерпретатора
uv run pytest                # тесты
uv run ruff check src tests  # линтер
sh scripts/stage1.sh         # демонстрация этапа 1
sh scripts/stage2.sh         # демонстрация этапа 2
sh scripts/stage3.sh         # демонстрация этапа 3
sh scripts/stage4.sh         # демонстрация этапа 4
```

## Структура

```
src/uvm/
    spec.py        команды УВМ, их поля и перевод в байты
    assembler.py   ассемблер: CSV → машинный код
    machine.py     память УВМ и выполнение команд
    interpreter.py интерпретатор: машинный код → дамп памяти в XML
tests/           тесты
programs/        программы на языке ассемблера
scripts/         демонстрационные скрипты
run.sh           скрипт запуска
```
